# ADR-0002: 프로필과 연결 CalDAV 컬렉션의 삭제 순서

## 상태

Accepted — 2026-08-11

## 문맥

출생 프로필과 캘린더 메타데이터는 SQLite에 있고, 동기화된 이벤트는 Radicale
CalDAV 컬렉션에 있다. 로컬 행만 삭제하면 출생 정보와 연결된 일정이 원격에 남아
사용자의 삭제 의도와 실제 보존 범위가 달라진다. 궁합 캘린더는 한 캘린더가 두
프로필을 참조하므로 어느 쪽을 지워도 연결 리소스를 빠뜨리지 않아야 한다.

## 결정

1. 캘린더 삭제 시 `last_synced_at`의 유무와 관계없이
   `DELETE /<user>/<slug>/`를 먼저 호출한다. 원격 생성 뒤 동기화 표기 저장이
   실패해도 컬렉션이 남을 수 있으므로 표시를 삭제 조건으로 사용하지 않는다.
2. CalDAV 404는 이미 지워진 상태로 간주하는 멱등 성공이다.
3. 원격 인증·연결 오류는 502로 반환하고 로컬 행을 보존한다(fail-closed).
4. 프로필 삭제는 `profile_id` 또는 `secondary_profile_id`로 연결된 모든
   캘린더를 수집한 뒤 원격 컬렉션을 지우고, 마지막에 SQLite 행을 삭제한다.
5. 마지막 삭제 단계의 동시성 race가 행을 찾지 못하면 404를 반환한다. 원격 삭제가
   이미 끝났으므로 재시도는 멱등적이다.
6. 운영자 UI는 삭제 전 연결 캘린더 수와 동기화 일정 삭제 범위를 한국어로
   설명하고 native confirmation을 요구한다.

## 근거와 결과

CalDAV 컬렉션은 RFC 4791의 WebDAV 리소스이며 삭제는 서버 컬렉션 상태의 변경이다.
데이터 주체의 삭제 요청을 실제 저장 계층 전체에 적용하려면 로컬 메타데이터와
원격 컬렉션을 하나의 논리적 사가로 취급해야 한다. 분산 트랜잭션을 가장하지 않고,
원격 삭제가 실패하면 로컬 삭제를 하지 않는 보수적 순서를 선택했다.

좋은 점은 잔존 원격 데이터와 부분 성공을 줄이고 재시도·감사를 설명할 수 있다는
것이다. 네트워크가 복구될 때까지 사용자가 로컬 행을 직접 지워 진행할 수 없다는
비용은 있지만, 민감한 출생 정보에는 가용성보다 삭제 일관성이 우선이다.

## 검증

- 동기화 캘린더 삭제에서 원격 DELETE가 로컬 DELETE보다 먼저 호출되는 테스트
- 주·보조 프로필 연결 캘린더 모두 삭제되는 테스트
- publisher 미설정 시 502와 로컬 보존 테스트
- 404 멱등 응답과 race 후 404 테스트
- 운영자 콘솔 정적 자산·한글 삭제 문구 테스트
