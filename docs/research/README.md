# 역법 조사와 구현 결정

## 범위와 해석

이 저장소는 사주를 문화적 계산 체계로 구현합니다. Homola는 팔자 계산을
년·월·일·시의 네 단위 각각에 천간과 지지를 배정하는 지식·계산 체계로
분석합니다. 이는 여기서 말하는 “예측”의 사실성이나 과학적 유효성을 입증하는
근거가 아닙니다. 제품은 계산 결과와 캘린더 조건만 제공하며 길흉 판단이나
미래 예측 문구를 생성하지 않습니다.

## 저장소의 계산 규칙

연구에서 단 하나의 보편적 운영 규칙이 도출되지 않는 부분은 제품 설정으로
분리했습니다.

- 입력은 양력의 출생지 현지 벽시각입니다.
- 기본 모드는 IANA 시간대의 표준 민간시(`civil`)입니다.
- 선택 모드 `true_solar`는 출생지 경도와 시간대의 표준 자오선 차이, 근사
  균시차를 분 단위로 보정합니다. 정밀 천문 관측용 모델은 아닙니다.
- 날짜는 현지 자정에 바뀝니다. 자시는 날짜 경계를 넘는 단일 이벤트가 되지
  않도록 `00:00–01:00`과 `23:00–24:00`로 나눕니다.
- 나머지 시지는 `01:00–03:00`부터 2시간 간격으로 구성합니다.
- 성별은 프로필 정보로 저장하지만 네 기둥 계산에는 영향을 주지 않습니다.
  대운의 순행·역행은 MVP 범위 밖입니다.
- 생성 범위는 요청 한 번에 최대 730일입니다.

## 구현과 독립 검증

생산 계산은 `lunar-python`이 제공하는 년·월·일주를 사용하고, 시주는 일간과
시지 인덱스에서 직접 계산합니다. 핵심 회귀값은 별도의 구현인 `sxtwl`과도
교차 확인했습니다.

```text
입력: 1990-06-15 08:30, Asia/Seoul, civil
결과: 庚午 / 壬午 / 辛亥 / 壬辰
확인: 일지 亥水, 시간 壬水
```

외부 라이브러리의 결과를 그대로 신뢰하지 않고 다음을 저장소 테스트에서
검증합니다.

- 전체 네 기둥과 오행 속성
- 자정 전후 일주 변경과 자시 분리
- 서울 경도 진태양시 보정 범위
- 규칙 필드·리터럴 허용 목록
- 1990-06-15의 `壬辰` 구간 `07:00–09:00`
- 결정적 UID와 비공개·투명 iCalendar 이벤트

## 한계

- 월주와 연주의 절기 경계는 선택한 라이브러리의 규칙을 따릅니다.
- 역사적 지역 시각이 불명확한 경우 IANA 시간대 데이터만으로 확정할 수
  없습니다.
- 진태양시 보정은 경도만 입력하며 위도, 고도, 관측 오차는 반영하지 않습니다.
- 학파별 야자시·조자시 관습을 모두 동시에 지원하지 않습니다. 기본 자정 경계는
  API 계약과 테스트에 명시되어 있습니다.
- 결과는 문화적 분류·일정 도구이지 의학·재정·법률 또는 중대한 삶의 결정을
  위한 근거가 아닙니다.
