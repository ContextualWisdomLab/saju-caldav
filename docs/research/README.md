# 역법 조사와 구현 결정

## 범위와 해석

이 저장소는 사주를 문화적 계산 체계로 구현합니다. Homola는 팔자 계산을
년·월·일·시의 네 단위 각각에 천간과 지지를 배정하는 지식·계산 체계로
분석합니다. 이는 여기서 말하는 “예측”의 사실성이나 과학적 유효성을 입증하는
근거가 아닙니다. 제품은 계산 결과와 캘린더 조건만 제공하며 길흉 판단이나
미래 예측 문구를 생성하지 않습니다.

## 저장소의 계산 규칙

연구에서 단 하나의 보편적 운영 규칙이 도출되지 않는 부분은 제품 설정으로
분리했습니다.

- 입력은 양력 또는 한국 음력의 출생지 현지 벽시각입니다. 음력은 평달·윤달을
  구분해 보존하고 한국천문연구원 기준 변환기로 양력 날짜를 얻은 뒤 명식을
  계산합니다.
- 태어난 시각이 알려지지 않은 입력은 원본 시각을 `NULL`과 별도 미상 표지로
  보존합니다. 날짜 단위 계산에는 현지 정오를 내부 기준점으로 사용해 일주를
  얻되, 이 값을 출생 시각으로 표시하거나 시주로 반환하지 않습니다. 두 사람
  추천은 일지만 사용하므로 계속 제공하고, 출생 시주를 참조하는 고급 규칙은
  거부합니다. 절기 전환일에는 내부 기준점 전후로 년주·월주가 달라질 수 있음을
  화면에 알립니다.
- 기본 모드는 출생 도시에서 선택한 IANA 시간대의 표준 민간시(`civil`)입니다.
  목록 밖 도시는 시간대만 직접 입력할 수 있습니다.
- 선택 모드 `true_solar`는 도시 목록에 서버 내부로 보관한 경도와 시간대의 표준 자오선 차이, 근사
  균시차를 분 단위로 보정합니다. 정밀 천문 관측용 모델은 아닙니다.
- 날짜는 현지 자정에 바뀝니다. 자시는 날짜 경계를 넘는 단일 이벤트가 되지
  않도록 `00:00–01:00`과 `23:00–24:00`로 나눕니다.
- 나머지 시지는 `01:00–03:00`부터 2시간 간격으로 구성합니다.
- 성별은 프로필 정보로 저장하지만 네 기둥 계산에는 영향을 주지 않습니다.
  대운의 순행·역행은 MVP 범위 밖입니다.
- 날짜 범위를 생략하면 프로필 시간대의 오늘 날짜부터 `시작일 + 365일`까지를
  양끝 포함으로 검색합니다. 날짜를 명시한 요청은 양끝을 포함해 최대 730개
  날짜까지 허용하고, DST의 존재하지 않거나 반복되는 현지 시각은 Python
  `zoneinfo`의 기본 offset·`fold=0` 규칙을 따릅니다.

### 두 사람 시간 모드

두 사람 시간 모드는 위 문헌의 관계 분류를 제품에서 투명하게 조합한 저장소
고유의 관례입니다. 어느 모드도 전통적인 궁합·길일 판정이나 ‘두 사람의 합’의
객관적 측정값이 아니며, 단일 학파의 정답으로 표현하지 않습니다.

#### 두 모드의 공통 검색 경계

- 기본 검색은 첫 번째 사람이 선택한 `civil` 민간시 또는 `true_solar` 진태양시를
  기준으로 09:00–23:00 안에 시작하고 끝나는 생활 시간만 비교합니다. 사용자가
  `24시간 전체`를 선택하면 새벽 후보도 포함합니다.
- 날짜 범위를 생략하면 프로필 시간대의 오늘부터 `오늘 + 365일`까지(양끝 포함)
  검색하고, 현재 시각보다 먼저 끝난 구간은 제외합니다. 명시 범위는 최대 730일을
  허용합니다.
- 각 날짜에는 점수와 시작 시각이 가장 좋은 후보 하나만 남기고, 동점이면 더 이른
  시간을 고릅니다. 점수는 비교와 정렬을 위한 제품 기준이지 확률·예측값·과학적
  측정치가 아닙니다.
- 프로필의 성별은 저장·표시용이며 현재 계산에 들어가지 않습니다. 남녀에 따라
  배우자성, 대운 순행·역행 등을 다르게 읽는 학파별 해석을 추가하려면 학파,
  적용 범위, 입력 근거와 별도 검증을 먼저 선택하는 독립 모드가 필요합니다.

#### 관계 작용 모드 (`pair_relation_activation`, 기본값)

- 두 사람의 출생 일지 사이의 기준 관계를 먼저 계산합니다.
- 후보 날짜의 지지와 후보 시간의 지지가 두 사람의 일지 모두와 긍정적인
  관계를 이루는 경우에만 관계 작용으로 셉니다. 한 사람에게만 맞는 지지는
  관계 작용으로 승격하지 않습니다.
- 기준 관계와 날짜·시간 작용에 제품 점수를 부여해 `relationship_score`를
  만들고, 두 개인 조건의 낮은 점수도 함께 확인합니다.
- 관계 작용이 날짜와 시간 모두에서 없거나 육충이 있거나 어느 개인 점수가
  60점 미만이면 후보에서 제외합니다.

#### 공통 조건 모드 (`shared_branch_relations`)

- 각 사람의 출생 일지와 후보 날짜의 지지, 후보 시간의 지지를 각각 비교합니다.
- 육합, 같은 삼합 계열, 같은 지지는 가점으로 설명하고 육충이 하나라도 있으면
  그 시간은 추천하지 않습니다.
- 두 사람 점수 중 낮은 쪽에 70%, 두 점수의 평균에 30%를 두어 한 사람에게만
  높은 후보가 상단에 오르기 어렵게 합니다.
- 이 모드의 `score`는 두 개인 점수의 균형값이며 관계 작용 점수와 구분합니다.
- 60점 이상이며 설명할 관계가 있는 후보만 남깁니다.

## 구현과 독립 검증

한국 음력 변환은 한국천문연구원 기준의 `korean-lunar-calendar`를 사용합니다.
변환된 양력 날짜의 년·월·일주는 MIT 라이선스의 `lunar-python 1.4.8` 소스를
저장소에 고정해 계산하고, 시주는 일간과 시지 인덱스에서 직접 계산합니다. 원본
PyPI 배포물은 소스 아카이브만 제공하므로, 이 방식은 컨테이너 빌드와 네트워크 없는
검증에서 임의의 빌드 스크립트를 실행하지 않게 합니다. 라이선스와 출처는
`THIRD_PARTY_NOTICES.md`, `licenses/lunar-python-MIT.txt`,
`licenses/korean-lunar-calendar-MIT.txt`에 보존합니다. 공개 저장소와 CI에는 실제
사용자의 회귀값을 두지 않고, 환경 변수로 주입하는 비공개 회귀 명령에서만 확인합니다.

현재 고정한 변환기 버전은 `korean-lunar-calendar==0.4.0`입니다. 이 버전이
문서화한 범위는 음력 `1000-01-01`부터 `2050-11-18`, 양력 `1000-02-13`부터
`2050-12-31`까지입니다. API의 연도 상한도 이 범위에 맞춰 2050년으로 제한하고,
범위 밖이나 존재하지 않는 윤달은 추측해 보정하지 않고 거부합니다.

외부 라이브러리의 결과를 그대로 신뢰하지 않고 다음을 저장소 테스트에서
검증합니다.

- 합성 예시의 네 기둥과 오행·한글 설명 속성
- 한국 음력 평달·실제 윤달 변환과 존재하지 않는 윤달 거부
- 입춘 절입 전후의 연주·월주 변경
- 자정 전후 일주 변경과 자시 분리
- 도시 선택에 따른 시간대·서울 경도 자동 적용과 진태양시 보정 범위
- 규칙 필드·리터럴 허용 목록
- 합성 예시의 이중 시각 구간과 현재 지역 날짜 이후 검색
- 두 사람 모드별 육충 제외·관계 작용 브리지·개인 균형 점수, 날짜별 한 후보와
  현재 이후 필터
- 출생 시각 미상 프로필의 음력 변환·일주 유지·시주 비노출과 두 사람 추천
- 결정적 UID와 공개 수준별 `CLASS`·투명·최소정보 iCalendar 이벤트

## 한계

- 월주와 연주의 절기 경계는 선택한 라이브러리의 규칙을 따릅니다.
- 역사적 지역 시각이 불명확한 경우 IANA 시간대 데이터만으로 확정할 수
  없습니다.
- 태어난 시각 미상 프로필은 시주를 확정할 수 없고 절기 전환일의 년주·월주에도
  불확실성이 남습니다. 내부 정오는 날짜 단위 계산 기준일 뿐 추정 출생 시각이
  아닙니다.
- 진태양시 보정은 도시별 대표 경도만 사용하며 위도, 고도, 도시 내부 위치 차이,
  관측 오차는 반영하지 않습니다. 목록 밖 도시의 진태양시는 현재 지원하지 않습니다.
- 학파별 야자시·조자시 관습을 모두 동시에 지원하지 않습니다. 기본 자정 경계는
  API 계약과 테스트에 명시되어 있습니다.
- 결과는 문화적 분류·일정 도구이지 의학·재정·법률 또는 중대한 삶의 결정을
  위한 근거가 아닙니다.
